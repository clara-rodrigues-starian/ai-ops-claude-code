Guia de rastreamento de horas: Claude Code e Figma Make — métodos nativos e complementares com exemplos de código

Claude Code — Terminal / CLI
Rastreamento de horas no Claude Code
3 métodos
1 Arquivos de sessão JSONL nativo
Claude Code salva cada sessão como um arquivo .jsonl em ~/.claude/projects/. Cada mensagem carrega um campo timestamp — o delta entre o primeiro e o último registro é a duração real da sessão. Explore a estrutura antes de rodar o script.
# Passo 1 — explorar a estrutura de sessões ls ~/.claude/projects/ # Passo 2 — listar arquivos de sessão por data find ~/.claude/projects -name "*.jsonl" | xargs ls -lt | head -10 # Passo 3 — calcular duração da sessão mais recente SESS=$(find ~/.claude/projects -name "*.jsonl" -print0 \ | xargs -0 ls -t | head -1) python3 - "$SESS" <<'EOF' import sys, json from datetime import datetime, timezone lines = [l for l in open(sys.argv[1]) if l.strip()] if len(lines) < 2: print("Sessão muito curta ou arquivo vazio.") sys.exit() def parse(line): return datetime.fromisoformat( json.loads(line).get("timestamp","").replace("Z","+00:00") ) t0, t1 = parse(lines[0]), parse(lines[-1]) mins = round((t1 - t0).total_seconds() / 60) print(f"Início : {t0.strftime('%Y-%m-%d %H:%M')}") print(f"Fim : {t1.strftime('%Y-%m-%d %H:%M')}") print(f"Duração: {mins} min") EOF
2 Wrapper de shell com log automático complementar
Substitui o comando claude por uma função que registra início, fim e projeto em um arquivo de log — sem mudar nada no fluxo de uso. Adicione ao ~/.zshrc ou ~/.bashrc e recarregue o terminal.
# Adicionar ao ~/.zshrc ou ~/.bashrc claude() { local START_TS=$(date +%s) local START_DT=$(date '+%Y-%m-%d %H:%M') local PROJECT=$(basename "$PWD") command claude "$@" local END_DT=$(date '+%Y-%m-%d %H:%M') local MINS=$(( ($(date +%s) - START_TS) / 60 )) echo "$START_DT → $END_DT | ${MINS}min | $PROJECT" \ >> ~/horas-claude-code.log echo "⏱ Sessão encerrada: ${MINS} min registrados." } # Recarregar: source ~/.zshrc # Ver log acumulado cat ~/horas-claude-code.log # Exemplo de saída: # 2025-06-09 14:03 → 15:01 | 58min | prototipo-clf-v3 # 2025-06-09 16:30 → 17:12 | 42min | prototipo-clf-v3
3 Comando /cost — proxy por intensidade nativo
Durante qualquer sessão ativa, /cost exibe tokens consumidos e custo estimado. Não mede tempo diretamente, mas é útil para comparar a intensidade relativa entre sessões de prototipagem e estimar esforço.
# Dentro de uma sessão ativa /cost # Saída típica: # Tokens usados — entrada: 18.4k | saída: 4.1k # Custo estimado da sessão: ~$0.058 # # Dica: anote o custo ao final de cada sessão junto # com o tempo manual → cria um calibrador pessoal # (ex: "cada $0.01 ≈ 8 min de trabalho no meu fluxo")
Limitação dos métodos 1 e 2: medem tempo de sessão aberta, não foco ativo. Uma pausa de 20 min sem fechar o terminal ainda aparece como contínua.
Figma Make — Browser / Web
Rastreamento de horas no Figma Make
3 métodos
1 Histórico de versões — interface visual nativo
Cada prompt executado no Figma Make cria uma versão com timestamp. O delta entre versões consecutivas é uma estimativa de quanto tempo você ficou em cada iteração. Acesse sem precisar de token ou script.
Caminho: Menu ▸ File ▸ Show version history (Cmd+Option+S) Leitura do histórico: 13:47 "Prompt: criar tela de boas-vindas" ← início 14:31 "Prompt: ajustar tipografia" ← Δ 44 min 14:58 "Prompt: adicionar animação de entrada"← Δ 27 min 15:40 "Prompt: revisão geral do fluxo" ← Δ 42 min Total: ~113 min Dica: renomeie versões com o contexto do prompt logo após executar — facilita imensamente a leitura depois.
2 Figma REST API — versões programáticas nativo
A API retorna todas as versões com created_at precisos. Ideal para consolidar dados de múltiplos arquivos em uma planilha de horas ou dashboard de projeto.
# Pré-requisitos: # TOKEN → figma.com/settings → Account → Personal access tokens # FILE_KEY → URL do arquivo: figma.com/file/{FILE_KEY}/... TOKEN="seu_token_aqui" FILE_KEY="seu_file_key_aqui" curl -s -H "X-Figma-Token: $TOKEN" \ "https://api.figma.com/v1/files/$FILE_KEY/versions" \ | python3 -c " import sys, json from datetime import datetime data = json.load(sys.stdin) versions = data.get('versions', []) prev = None for v in reversed(versions): dt_str = v['created_at'][:19].replace('T',' ') dt = datetime.fromisoformat(dt_str) label = v.get('label') or 'iteração' delta = '' if prev: mins = round((dt - prev).total_seconds() / 60) delta = f' Δ {mins} min' print(f'{dt_str} {label}{delta}') prev = dt "
3 Extensão de browser — Toggl Track ou Clockify complementar
Único método que mede tempo de foco ativo real — não depende de saves. A extensão detecta a aba figma.com e inicia o timer automaticamente. É o método mais confiável para horas faturáveis.
Toggl Track — configuração para Figma Make: 1. Instalar: toggl.com/track/chrome-extension 2. Abrir extensão → Settings → Autotracker → New rule: URL contains : figma.com Project : Checklist Fácil Tag : figma-make, prototipo 3. O timer inicia automaticamente ao abrir qualquer arquivo Figma e pausa ao trocar de aba. 4. Exportar: app.toggl.com/reports Filtrar por tag "figma-make" Exportar CSV → colar na planilha de horas Alternativa gratuita: Clockify tem a mesma função de autotracker por URL (clockify.me/chrome-extension)
Limitação dos métodos 1 e 2: medem timestamps de saves/prompts, não tempo de tela ativo. Períodos longos entre iterações podem incluir inatividade real. O método 3 é o único que isola o tempo de foco efetivo.
Combinação recomendada para protótipos navegáveis
Claude Code: wrapper de shell (M2)  +  Figma Make: Toggl com autotracker (M3) — ambos rodam em paralelo sem interromper o fluxo
